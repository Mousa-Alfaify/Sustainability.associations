# مُحرك الاستدامة للجمعيات

منصة تحلل الوضع المالي والتشغيلي للجمعيات الأهلية، ثم تبني لها **محفظة استدامة مالية** من مصادر دخل متكررة تغطي المصاريف التشغيلية (الرواتب، الإيجارات، الأنظمة، الخدمات الإدارية) بدلًا من الاعتماد على التبرعات الموسمية.

> ليست منصة تبرعات. هي أداة تشخيص + تخطيط مالي للقطاع غير الربحي.

**العرض المباشر:** <https://mousa-alfaify.github.io/Sustainability.associations/>

| # | الخطوة | الشاشة | الرسالة |
|---|--------|--------|---------|

| 3 | مؤشر الاستقلال المالي | `/dashboard` أو `/independence` | **35.4 / 100** — «استقرار ضعيف»، مع تفصيل المكونات الأربعة |
| 4 | اضغط **«حلّل جمعيتي»** | `/dashboard` | يظهر التشخيص: كل ملاحظة مدعومة برقم من ملف الجمعية |

| 6 | اضغط **«طبّق السيناريو المقترح»** | `/scenarios` | المؤشر يرتفع بصريًا **35.4 ← 82.1**، والفجوة تتحول من **−45,000 ر.س إلى 0** |
| 7 | رسالة الختام | `/scenarios` | «جمعيتك أصبحت قادرة على تغطية مصاريفها التشغيلية من مصادر دخل أكثر استدامة» |

## أرقام الجمعية التجريبية (جمعية نماء للتنمية)

**المصروف التشغيلي الشهري = 60,000 ر.س**
الرواتب 40,000 · الإيجار 8,000 · التقنية 4,000 · الإدارة 5,000 · أخرى 3,000

**الدخل الحالي**
تبرعات موسمية 450,000/سنة · منح مشاريع 200,000/سنة · عقود خدمات 10,000/شهر · وقف 5,000/شهر
الاحتياطي: 120,000 ر.س

**النتيجة**: إيراد متكرر 15,000 فقط ← فجوة 45,000 ر.س شهريًا، وفترة أمان شهران.

**محفظة الاستدامة المقترحة** (تغلق الفجوة بالكامل):

| المصدر | إضافة شهرية | إجمالي الخط بعد التنفيذ |
|--------|-------------|--------------------------|
| عقود خدمات مع الشركات والجهات الحكومية | +10,000 | 20,000 |
| وقف رقمي واستثمار اجتماعي | +10,000 | 15,000 |
| برامج تدريب ومنتجات معرفية مدفوعة | +10,000 | 10,000 |
| شراكات مسؤولية اجتماعية طويلة المدى | +10,000 | 10,000 |
| توفير من تحسين الكفاءة | 5,000 | — |
| **الإجمالي** | **55,000 إيراد + 5,000 توفير** | **تغطية 60,000 ر.س** |

## المعادلات المالية

| المؤشر | المعادلة |
|--------|----------|
| المصروف التشغيلي الشهري | الرواتب + الإيجارات + التقنية + الإدارة + التسويق + أخرى |
| الإيراد الشهري المتكرر | مجموع المصادر المتكررة فقط (تُستبعد التبرعات الموسمية والمنح المقيدة) |
| الفجوة التشغيلية | الإيراد المتكرر − المصروف التشغيلي |
| فترة الأمان المالي | الاحتياطي النقدي ÷ المصروف التشغيلي الشهري |
| الاعتماد على الموسمية | الدخل الموسمي ÷ إجمالي الدخل |
| العدد الفعّال لمصادر الدخل | 1 ÷ مؤشر هيرفندال (HHI) لتركّز مصادر الدخل |

### مؤشر الاستقلال المالي (0–100)

```
Score = 30 × min(Coverage / 1, 1)
      + 25 × min(EffectiveSources / 5, 1)
      + 25 × min(RunwayMonths / 6, 1)
      + 20 × clamp((0.70 − SeasonalDependency) / (0.70 − 0.20), 0, 1)
```

الأوزان والأهداف المرجعية معرّفة في مكان واحد وقابلة للتعديل:
`lib/finance/independence-score.ts` → `SCORE_WEIGHTS` و `SCORE_TARGETS`.

**التصنيف**: 0–30 خطر مالي مرتفع · 31–50 استقرار ضعيف · 51–70 استقرار متوسط · 71–85 استقرار جيد · 86–100 استدامة مالية قوية.

> ملاحظة منهجية مقصودة: المؤشر يقيس **هيكل** الاعتماد لا **حجم** التمويل، لذلك قد يرتفع شكليًا عند توقف التبرعات الموسمية. مستشار الاستدامة يوضّح ذلك صراحةً في إجابة اختبار الضغط، ولهذا يُقرأ المؤشر دائمًا مع حجم الدخل وفترة الأمان.

### قاعدة بناء المحفظة

1. كل مصدر في الكتالوج يُقيَّم بدرجة ملاءمة (`fitScore`) من ملف الجمعية: الأصول، الخبرات، الشراكات، حجم الفريق، المصادر القائمة.
2. عدد المصادر = بين 3 و5، بحيث **لا يتجاوز أي مصدر جديد 20% من المصروف التشغيلي** (قاعدة التنويع).
3. الفجوة المتبقية (بعد التوفير من الكفاءة) تُوزَّع على المصادر المختارة حسب سعتها النسبية، مقرّبة لأقرب 500 ر.س.

## التقنية

Next.js 14 (App Router) · TypeScript · Tailwind CSS · shadcn/ui (Radix) · Recharts · واجهة عربية RTL بالكامل.

## النشر

يُنشر الموقع تلقائيًا على GitHub Pages عند كل دفع إلى الفرع `main` عبر سير العمل في `.github/workflows/deploy.yml`.

البناء في وضع النشر يُصدّر الموقع كملفات ثابتة تحت مسار المستودع:

```bash
GITHUB_PAGES=true npm run build
```

المخرجات في مجلد `out/`. أما التطوير المحلي فيبقى بدون بادئة مسار على `http://localhost:3000`.

لتغيير اسم المستودع لاحقًا، عدّل قيمة `repository` في `next.config.mjs` فقط.

## الجاهزية للمرحلة القادمة

- **Supabase / PostgreSQL**: طبقة الحفظ معزولة في `lib/store/app-store.tsx` (حاليًا `localStorage`). الاستبدال يتم في هذا الملف وحده، وأنواع البيانات في `lib/types.ts` تقابل جداول: `organizations`, `expenses`, `income_streams`, `scenarios`, `revenue_sources`.
- **مصادقة حقيقية**: `login/logout` في نفس الملف، وحماية المسارات في `components/shell/app-shell.tsx`.
- **ذكاء اصطناعي**: `answerQuestion(question, context)` في `lib/advisor/engine.ts` هي نقطة الدخول الوحيدة — يُستبدل محرك القواعد باستدعاء نموذج لغوي مع نفس الـ `AdvisorContext` دون تعديل أي مكوّن واجهة.
